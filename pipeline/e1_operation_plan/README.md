# E1 운영계획서 추출 실험 키트

운영계획서 PDF 5건을 Claude로 추출해서 기관 기준표(정답셋)와 비교하는 실험입니다. 구현 검토 7장 E1의 합격 기준은 **핵심 필드 90% 이상 일치, 근거 쪽 번호가 맞음**입니다.

실험용이라 Python으로 만들었습니다. 합격하면 같은 `schema.json`과 `prompt_system.md`를 Java(E3)로 옮깁니다.

## 들어 있는 것

| 파일 | 역할 |
|---|---|
| `schema.json` | 추출 결과 JSON 스키마(structured outputs용). 필드마다 값, 쪽 번호, 인용문을 받습니다 |
| `schema_lite.json` | 핵심 필드만 담은 스키마. **현재는 이쪽만 씁니다**(아래 6장). 채점에 쓰는 기관 13항목과 사람 판정 5항목이 모두 들어 있습니다 |
| `build_schema.py` | 두 스키마를 만드는 코드. 스키마를 고칠 때는 이 파일을 고치고 다시 실행합니다 |
| `prompt_system.md` | 시스템 프롬프트(추출 규칙, 체크 표시 읽는 법, 직무 나누는 법, 문서 내부 불일치) |
| `run_extract.py` | PDF → Claude API → `out/*.json` |
| `score.py` | 정답셋 비교, 인용문 원문 대조, 사람 판정표 생성 → `e1_report.md` |
| `data/answer_institutions.csv` | 기관 기준표 18곳(정답셋 초안) |

## 1. 준비 (한 번만)

1. Python 3.10 이상에서 설치합니다.
   ```
   pip install anthropic pypdf openpyxl
   ```
2. [Claude Console](https://platform.claude.com) → Settings → Billing에서 크레딧을 충전하고(자동 충전은 끔), Settings → API keys에서 키를 만듭니다.
3. 충전한 크레딧만큼만 쓰이므로 소액(예: $10)만 충전해 두면 그 이상 나가지 않습니다.
4. 환경변수에 키를 넣습니다.
   - macOS·Linux: `export ANTHROPIC_API_KEY=sk-ant-...`
   - Windows PowerShell: `$env:ANTHROPIC_API_KEY="sk-ant-..."`

## 2. 대상 5건

| 기관 | 쪽 | 고른 이유 |
|---|---|---|
| 선도소프트 | 3 | 교육목표와 전공 요건이 문서 안에서 엇갈림(M2 사례) |
| 세정 | 5 | 직무기술서 블록은 2개인데 부서명 칸에 팀이 7개 들어 있다. 팀마다 직무를 나누는지 확인(센터 참여기관 리스트도 7행) |
| 비욘드마케팅그룹 | 3 | 산업분류코드가 쪽마다 다름(M2 사례) |
| 챔프스터디 | 5 | 전체 이미지 PDF. 실습기간 연도 오기, 직무 표가 다른 서식 머리글로 이어짐 |
| 제이숲 | 8 | 일부 이미지(15.8MB), 직무 5개 |

총 24쪽입니다. 예상 비용은 약 $0.4~0.8(약 500~1,100원)이고, 실행 시간은 5~10분입니다.

## 3. 실행

드라이브 사본의 `2. 기관별 운영계획서 및 소개서` 폴더를 `D`로 두고, 기관 폴더를 넘깁니다. 폴더를 넘기면 그 안의 `*운영계획서*.pdf`만 골라 쓰고, 소개서는 제외됩니다.

> **`--lite`를 붙입니다.** 전체 `schema.json`은 구조화 출력의 문법 한도를 넘습니다(2026-09-30 확인, `$ref`로 줄여도 마찬가지). 채점에 필요한 필드는 lite에 다 있습니다.

**Windows PowerShell**
```
$D = "C:\...\[서경대] 2026-2학기 현장실습학기제\2. 기관별 운영계획서 및 소개서"
python run_extract.py --lite "$D\6. 주식회사 선도소프트" "$D\2. (주) 세정 (웰메이드, 인디안, 디디에두보)" "$D\12. (주) 비욘드마케팅그룹" "$D\4. (주) 챔프스터디 (해커스)" "$D\8. (주)제이숲 (앙또미뇽)"
python score.py --pdf-root "$D"
```

**macOS·Linux**
```
D="$HOME/Desktop/[서경대] 2026-2학기 현장실습학기제/2. 기관별 운영계획서 및 소개서"
python run_extract.py --lite "$D/6. 주식회사 선도소프트" "$D/2. (주) 세정 (웰메이드, 인디안, 디디에두보)" "$D/12. (주) 비욘드마케팅그룹" "$D/4. (주) 챔프스터디 (해커스)" "$D/8. (주)제이숲 (앙또미뇽)"
python score.py --pdf-root "$D"
```

## 4. 사람 판정 (직무 단위)

정답셋에 직무별 값이 없어서 전공·인원·학년·학점·요일시간은 사람이 판정합니다.

1. `review_jobs.csv`를 엑셀로 엽니다. 직무마다 한 줄이고, 전공 인용문이 원문과 맞는지 확인한 결과도 들어 있습니다.
2. 원본 PDF를 옆에 띄우고 `판정_전공`, `판정_인원`, `판정_학년`, `판정_학점`, `판정_요일시간` 칸에 O나 X를 적어 저장합니다(CSV 형식 유지).
3. 판정을 합쳐 다시 채점합니다.
   ```
   python score.py --pdf-root "$D" --review review_jobs.csv
   ```

## 5. 결과 읽기 (`e1_report.md`)

- **기관 단위 자동 비교**: 사업자번호, 개업일, 산업분류코드, 종업원 수, 규모, 상장, 운영유형, 연장실습, 근로계약, 실습지원비, 식사지원, 직무 수, 모집인원 합계를 비교합니다(문서당 13개).
- **직무 단위 사람 판정**: 4장에서 채운 O/X입니다.
- **E1 판정**: 위 두 가지를 합친 일치율이 90% 이상이면 합격입니다.
- **인용문 확인**: 텍스트가 있는 쪽은 인용문이 그 쪽에 실제로 있는지 자동으로 봅니다. 결과는 일치 / 쪽 틀림 / 원문에 없음으로 나오고, 이미지 쪽은 사람이 확인합니다. "쪽 번호까지 맞은 비율"이 E1의 두 번째 기준입니다.
- **알려진 불일치 탐지**: 선도, 비욘드, 챔프스터디 사례를 잡았는지 보여줍니다. M2 참고 지표이고 합격 기준에는 넣지 않습니다.

정답셋도 사람이 옮긴 초안입니다. 불일치가 나오면 원본을 보고 AI가 틀렸는지, 정답셋이 틀렸는지 판단해서 메모에 남깁니다.

## 6. 오류가 날 때

| 증상 | 대처 |
|---|---|
| `400 ... The compiled grammar is too large` 또는 `Schema is too complex` | `--lite`를 붙여 다시 실행합니다(핵심 필드만 추출). 필드 수가 아니라 스키마 전체 크기가 기준이라, 필드를 조금 줄이는 것으로는 넘어가지지 않습니다 |
| `max_tokens에서 잘림` | 기본값이 이미 20,000입니다(비스트리밍 상한은 약 21,000). 직무가 많은 문서라면 `--lite`로 다시 실행합니다 |
| `401` / 인증 실패 | 환경변수 `ANTHROPIC_API_KEY`를 확인합니다 |
| 크레딧 부족 | Console에서 충전합니다 |
| 32MB 한도 경고 | 해당 PDF를 압축하거나 쪽을 나눕니다(5건 중에는 해당 없음) |

## 7. 저장소 주의 (공개 저장소)

`out/`, `data/`, `review_jobs.csv`, `e1_report.md`에는 사업자번호 같은 화면 비노출 값이 들어 있습니다. 이 키트를 저장소에 넣을 때는 같이 들어 있는 `.gitignore`로 이 파일들을 빼고, 코드만 커밋합니다.

## 8. 끝나면

노션 개발 설계 표의 E1 행에 아래 네 가지를 적습니다.
- 자동 비교 %, 사람 판정 %, 쪽 번호 정확도 %
- 틀린 필드 목록
- 실제 비용
- 합격 여부

합격하면 E3(Java SDK 연동)에서 이 스키마와 프롬프트를 그대로 씁니다.
