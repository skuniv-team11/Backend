# ADR-0032 실습 뒤 커리어: 직무를 NCS 세분류로 풀고, 실습 내용에서 다룬 능력단위를 AI가 고르고 서버가 구절을 대조한다

- 상태: 확정 (2026-10-10 — 박경원 결정: 새 API 설계안 'P0부터'. 직무 → 세분류·넓혀 갈 세분류·직업 보정은 **이 PR 병합으로 사람이 확인한 것으로 본다**)
- 문제
  - 학기 실습은 사실상 한 번이고(표준 현장실습 D 12학점, 재학 중 18학점까지) 대부분 그 회사 채용과 이어지지 않는다(2026-2 채용연계형 13/40). 수행결과보고서(별지 제9호)는 학점 서류로 내고 끝나, 어떤 직무 역량을 채웠고 다음에 무엇을 하면 되는지 알려 주는 곳이 없다.
  - 기획안 ②: 실습이 끝날 때 '실습 내용'을 NCS 능력단위로 정리하고, 넓혀 갈 직무와 이어지는 직업을 보여 준다.
- 결정
  - **NCS는 시드로**(ADR-0002): e6 `ncs_units.csv`(한국산업인력공단 NCS, 2026-09-30 적재 15,520건)와 한국고용정보원 '직업능력 코드매핑정보'(2025-11-26, 공공데이터포털 15154290, NCS ↔ 한국고용직업분류)를 `pipeline/seed/ncs_seed.py`가 `ncs.json`으로 만들고 `to_sql.py`가 `R__seed.sql`에 함께 넣는다. 실행 중 공공 API 호출은 없다.
  - **직무 → 세분류 하나**: 40개 모두 사람이 직무 원문과 능력단위를 보고 골랐다(`curated/job_ncs.csv`, 고른 까닭 포함). 글자 n-gram 유사도 후보는 엉뚱한 세분류(주얼리마케팅·카드상품개발)가 많아 쓰지 않았다. 예: 소서 국내 마케팅 → 마케팅전략기획, 세정 인플루언서 → 소셜미디어방송서비스, 빌딩닥터 → 유지관리.
  - **능력단위 정리**: '(구버전)'은 빼고, 같은 세분류 안에서 이름이 같은 단위(띄어쓰기·가운뎃점만 다름 — 'STP전략 수립' 16v3 · 'STP 전략 수립' 21v4)는 개정 연도가 늦은 것 하나. 수준이 0(원본에 없음)이면 null. 마케팅전략기획 18 → 11개.
  - **넓혀 갈 직무**: 세분류마다 3개를 사람이 골랐다(`curated/ncs_expand.csv`). 관계(같은 소분류·같은 중분류·다른 분야)는 코드로 정한다. 같은 소분류만 쓰면 소셜미디어방송서비스의 형제가 방송시스템운영 같은 기술 직무라 쓸모가 없어서다.
  - **이어지는 직업**: 공식 연계표(세분류 8자리 + 그 소분류 6자리). 연계표에 없는 세분류 7개(소셜미디어방송서비스·전자상거래·이러닝콘텐츠개발·자금·문화콘텐츠기획·해외영업·유지관리)는 같은 표의 직업에서 사람이 골라 더하고(`CURATED`), 소분류 전체에 붙어 엉뚱한 직업(디자인 세분류의 건축가·조경 기술자, 회계·감사의 관세사 등)은 뺐다(`curated/ncs_occupations.csv`). 표에 맞는 직업이 없으면 비운다(헤어미용 — 표에 미용사가 없다). 직업 코드는 표에 있는 것만 쓴다(지어내지 않는다).
  - **커리어 리포트**(#34): 학생이 '실습 내용'(100~3,000자)을 붙여 넣으면 AI(직무 탐색과 같은 Sonnet·키·한도)가 그 직무 세분류의 능력단위 중 실제로 해 본 것을 고르고, 서버가 대조한다 — 목록 안 단위, 학생 구절이 실습 내용 한 문장 안에 그대로, 이유 해요체. 개정 표기만 틀린 코드(_21v4 ↔ _21v5)는 단위 번호(앞 10자리)로 찾는다(실제 호출에서 나왔다). 못 다룬 단위는 '다음에 채울 것'. AI가 없거나 실패하면 목록만(`source: NONE`).
  - 개인정보: 직무 탐색과 같다(동의, 가리기, 계정당 1건, 탈퇴 때 삭제, 학과·학년·평점은 보내지 않음).
  - V10: `ncs_subcategory`·`ncs_unit`·`occupation`(부모, code로 upsert — 리포트가 단위를 가리킴), `ncs_occupation`·`job_ncs`·`ncs_expand`(통째로 다시), `career_report`·`career_report_unit`.
- 이유
  - 직무 ↔ 세분류는 틀리면 리포트 전체가 틀리므로 AI 초안 없이 사람이 고르고 PR로 확인받는다(AGENTS.md '사람 확인한 시드'). 실습 내용 ↔ 능력단위는 글의 뜻을 읽어야 해서 AI가 하고, 지어내지 못하게 구절을 코드가 대조한다(기획안 설계 원칙 2).
- 확인
  - `CareerApiTest`(가짜 AI): 122의 세분류·단위 11개·넓혀 갈 직무·직업, 140 직업 없음, 대조(문장 걸침·목록 밖·중복 버림), 대신하기 3가지, 동의·길이·404.
  - 실제 API(10/10, 예시 실습 내용 · 122): 4.4초, 3개 단위(신상품 기획·마케팅 시장 환경 분석·마케팅 성과파악) 모두 대조 통과(그중 1개는 판 번호만 틀린 코드 → 단위 번호로 찾음). 입력 약 2,400토큰.
- 남은 것: 보고서 → 능력단위 정확도는 팀이 먼저 붙인 정답으로 11/1 전에 잰다(기획안). 실습한 직무는 지금 학생이 고른다 — 매칭·선발 기능이 들어오면 배정된 직무로 잇는다.
- 다시 볼 때: NCS가 개정될 때(ncs_load.py 다시), 새 회차 직무가 들어올 때(job_ncs.csv에 행 추가 — 없으면 ncs_seed.py가 멈춘다), 직업 연계표가 갱신될 때.
