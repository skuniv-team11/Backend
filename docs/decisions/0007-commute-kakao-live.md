# ADR-0007 통근 시간은 카카오 대중교통 API를 실시간으로 부르고 저장하지 않는다

- 상태: 확정 (2026-10-01)
- 결정
  - 학생 프로필에 **사는 곳**(서울·인천·경기 시·군·구, 선택)을 둔다. 정확한 주소는 받지 않는다. 저장은 다른 프로필 값과 같이 [저장]+동의 때만.
  - 직무 상세를 열 때 서버가 카카오 대중교통 길찾기(`GET https://dapi.kakao.com/v2/routing/publictraffic`)를 1번 부른다. 출발 = 사는 곳의 시·군·구청 좌표(없으면 서경대), 도착 = 근로지 좌표.
  - 결과는 **DB·캐시에 저장하지 않는다.** 목록 카드(추천·지망)에는 통근을 넣지 않는다.
  - 출발·도착 좌표는 행정안전부 도로명주소 좌표제공 API로 오프라인에서 구해 시드로 넣는다(UTM-K → WGS84 변환). 카카오 로컬 API(주소 → 좌표)는 쓰지 않는다.
- 이유
  - 학생에게 의미 있는 건 서경대가 아니라 사는 곳에서 근로지까지의 시간이다.
  - 카카오 운영정책은 API 결과와 결과로 만든 가공 데이터를 DB·캐시에 저장하거나, 경로를 미리 조회해 보관하는 것을 금지한다(데브톡 공식 답변 2026-09-17). 로컬 API 결과도 저장할 수 없다. 그래서 미리 계산이 아니라 실시간 조회이고, 시드에 넣는 좌표는 저장이 허용되는 공공 API(이용허락범위 제한 없음)에서 받는다.
  - REST 키라 IP 등록이 없어 Render에서 바로 부를 수 있다. 무료는 개발자 계정에서 카카오맵을 **처음** 켠 앱 하나에 하루 1,000건(2026-07-21 정책). 두 번째 앱부터는 비즈월렛 연결·유료(건당 10원).
  - ODsay는 결과 저장에 회사의 사전 동의가 필요하고 무료 하루 30건이라 맞지 않는다(ADR-0002 개정).
- 결과
  - 실행 중 외부 호출이 하나 늘어난다. 실패·한도 초과면 통근 칸만 '불러오지 못했어요'로 두고 나머지 화면은 그대로다(200 + `available: false`, `docs/api/README.md`).
  - 호출 제한: 계정당 1시간 30회, 서버 전체 하루 900회(무료 1,000건 안에서 멈춘다). 3초를 넘기면 포기한다.
  - 카카오 API에는 출발 시각 값이 없다. 조회 시각에 따라 결과가 바뀌는지는 키를 받은 뒤 낮·밤에 한 번씩 불러 확인한다.
  - 키: `KAKAO_REST_API_KEY`(Render 환경변수, 로컬). 카카오맵을 켠 적 없는 팀 계정에서 앱을 만든다. 비즈월렛은 연결하지 않는다(한도를 넘으면 과금 대신 실패하도록).
  - 로그에 사는 곳 코드·좌표를 남기지 않는다.
  - 좌표 키 발급(도로명주소)은 10/1부터 대기다. 좌표제공 API는 주소가 아니라 주소 코드를 받으므로 도로명주소 검색 API와 함께 쓴다(키 2개). 그동안 근로지 좌표는 비어 통근 칸이 '불러올 수 없음'이고, 사는 곳(`area`)은 좌표가 필수라 시드에 넣지 않으므로 출발점은 서경대뿐이다. 통근 칸을 실제 근로지로 시연하기 전에 재개한다.
- 다시 볼 때: 하루 1,000건을 넘는 운영 단계, 또는 카카오 운영정책·무료 쿼터가 바뀔 때.
