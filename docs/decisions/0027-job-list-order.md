# ADR-0027 전체 직무 목록은 판정 → 모집 중 → 적합도 순으로 보여 준다

- 상태: 확정 (2026-10-07 결정 — 사용자 동의 '그대로 진행')
- 문제
  - 판정 목록(#14, 직무 찾기 화면의 전체 직무)은 판정 안에서 센터 참여기관 리스트 순번이었다. 프론트는 이 순서를 그대로 보여 주고 필터·검색만 한다. 그래서 추천 카드(적합도 순) 바로 아래 목록은 나와 상관없는 순서였다.
  - 기준일에 마감된 직무도 리스트 순번대로 섞였다. 예: 101 AE(리스트 1번, 7/18 센터 모집마감)는 판정 묶음 맨 위에 '마감'으로 떴다. 추천은 마감 직무를 이미 뺀다(ADR-0016).
  - 적합도는 추천 5개에만 붙고 점수는 응답에 없어서(ADR-0018·0026), 프론트가 목록을 적합도 순으로 다시 정렬할 수 없다.
- 결정
  - 목록 순서 = **판정**(지원 가능 → 확인 필요 → 지원 불가) → 같은 판정 안에서 **모집 중 먼저**, 기준일(추천과 같은 `replay.defaultAsOf`, 운영 때는 오늘)에 마감된 직무는 아래 → 모집 중인 지원 가능·확인 필요는 **적합도 순** → 나머지(지원 불가, 마감)는 센터 리스트 순번.
    - 판정 묶음을 먼저 두는 건 화면의 탭·숫자가 판정별이고, 지원할 수 있는 자리가 먼저 보여야 해서다. 적합도만으로 줄 세우면 지원 불가가 위로 올 수 있다.
    - 적합도 순 = 추천할 이유가 있는 직무 먼저(추천과 같은 순서 — 높음 → 점수 → 리스트 순번), 그다음 이유가 없는 직무를 같은 순서로. 그래서 지원 가능 묶음 맨 위가 추천 카드와 같은 순서로 이어지고, 이유 없이 지원비·채용연계 가점만 높은 직무가 추천 직무 사이에 끼지 않는다.
    - 마감일 순은 쓰지 않는다. 2026-2 직무 40개 중 37개는 마감일이 없다.
    - 지원 불가는 적합도를 매기지 않으므로(ADR-0024) 리스트 순번.
  - 응답 모양은 그대로다. 적합도·점수는 판정 응답에 넣지 않는다(순서에만 쓴다). 프론트는 고칠 것이 없다.
  - 구현: 판정은 점수를 모르므로 `eligibility.FitOrder` 인터페이스로 순위만 받고, `recommend.FitListOrder`가 추천과 같은 `FitScorer`로 계산한다. `RecommendService`를 거치지 않고 저장소를 직접 써서 빈이 돌지 않게 했다.
- 결과
  - 예시 학생(메이크업디자인학과 3학년, '뷰티 브랜드 SNS 마케팅'): 목록 맨 위 5개가 추천 카드와 같은 순서(국내 마케팅 · 해외 마케팅 · AMD · 세정 SNS, 영상 · 국내 인플루언서).
  - 광고홍보콘텐츠학과 4학년: 101 AE가 같은 판정 묶음의 맨 끝으로 간다.
  - 추천 5개가 목록 맨 위에 한 번 더 보인다. 전체 목록이라 그대로 두고, 필요하면 프론트가 그 줄에 '추천' 표시를 단다(응답 변경 없음 — 추천 응답의 `jobId`로 알 수 있다).
  - 판정 요청마다 키워드 유사도를 한 번 더 계산한다(직무 40개, 외부 호출 없음).
- 다시 볼 때: 직무 수가 크게 늘어 목록 정렬 비용이 보일 때, 화면이 판정 탭 대신 다른 묶음(기관·마감 등)을 쓰게 될 때, 지원 불가 안에서도 '조건 하나만 모자란 직무'를 먼저 보여 주자는 요구가 있을 때.
