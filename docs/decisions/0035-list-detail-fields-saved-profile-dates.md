# ADR-0035 목록·상세에 필요한 값을 한 응답에, 프로필은 저장한 것 기준, 기준일·마감은 한 곳에서

- 상태: 제안 (2026-10-10 — 박경원 요청: 백엔드 설계 재검토(Notion '백엔드 설계 재검토 (10/10)')를 "여기서 진행해줘". 재검토안 C·D·E — 더하기만 하는 1단계. PR 병합으로 확정한다)
- 문제
  - v2 화면 한 장이 같은 값을 여러 API에서 나눠 받는다.
    - 직무 찾기 목록: 조회수를 직무마다 #25로(최대 40번), NCS 세분류 이름을 직무마다 #33으로, 담기·순위를 #19로 부른다.
    - 직무 상세: 내 판정 한 줄을 보려고 #14로 40개 전부를 받는다. 조회수는 #25로 따로 부른다.
  - 프로필을 받는 길이 두 가지다. #14·#28·#29는 요청 본문, #30·#32·#37·#44는 저장한 프로필이다. 본문 프로필로 탐색한 뒤 저장한 프로필이 다르면, 결과를 다시 열 때 판정이 바뀐다.
  - 기준일과 마감 판정이 여러 곳에 흩어져 있다.
    - 기준일: 판정·추천·탐색은 설정값(7/23), 지원서·내 현장실습은 체험 시점·오늘, 조회수·센터는 각자 오늘.
    - 마감 판정: `EligibilityService`·`ApplicationViews`·`TimelineService`·`SignalCalculator` 네 곳이다. 마지막만 '모집 종료일 뒤면 마감'을 더 본다.
- 결정
  - **C 목록·상세에 함께 보이는 값**(응답에 더하기만, 기존 필드는 그대로)
    - #14 행: `ncs`(세분류 `{code, name}`, #33과 같은 세분류), `views`(#25와 같은 값), `planned`(내가 담았는지), `planRank`(1~3 또는 null).
      - 재검토안에는 `planRank`만 있었다. 그런데 null만으로는 '담지 않음'과 '담았지만 순위 없음'을 가를 수 없어 `planned`를 더했다.
    - #17: `views`·`todayViews`(이번 조회까지 센 뒤), `planned`·`planRank`, `myEligibility`(저장한 프로필로 본 `{verdict, majorMatch, reasons}`, #14 행과 같은 값).
      - 저장한 프로필이 없거나 센터면 null이다.
    - #25는 2단계(프론트 v2 전환 뒤)에 지운다.
  - **D 프로필은 저장한 것 기준**: #14·#28·#29의 본문 `profile`을 선택으로 바꾼다.
    - 빼면 저장한 프로필(#8)로 보고, 둘 다 없으면 404 `PROFILE_NOT_FOUND`다.
    - 저장하지 않고 써 보는 길(본문)은 그대로 둔다.
    - #15·#16·#23·#27은 2단계에 지울 API라 바꾸지 않는다(필수 그대로).
  - **E 기준일·마감을 한 곳에서**(`reference/ReferenceDates`)
    - **모집 판정 기준일**(`recruit`): 판정·추천·탐색·지망 점검이 쓴다. 리플레이 중에는 `replay.defaultAsOf`이고, 운영 때 오늘로 바꿀 자리가 이 하나다.
    - **진행 기준일**(`progress`): 요청한 날 → 체험 학생의 기준일 → 오늘(한국 시간). 지원서·내 현장실습이 쓴다.
    - '오늘'(조회수의 날짜·센터 지원서 화면)도 여기서 읽는다.
    - **마감**(`AsOf.closed`): `closesOn` ≤ 기준일이거나 기준일이 회차 모집 종료일 뒤면 마감이다. 판정 목록·탐색 후보·지원서 지망·타임라인 담은 직무·모집 신호가 모두 이 규칙 하나를 쓴다.
      - 모집 판정 기준일은 늘 모집기간 안이라, 판정·추천·탐색 결과는 바뀌지 않는다.
      - 바뀌는 것: 모집이 끝난 뒤 진행 기준일로 본 지망·담은 직무는, 마감일이 없어도 '마감'이다.
    - 현황판(#24)의 `asOf`는 모집 신호 계산에만 쓰이고, 그 계산은 2단계에 지운다. 그래서 이번에는 바꾸지 않는다.
- 이유
  - 직무 찾기 화면의 호출이 최대 47번에서 2번(#14·#30)으로 준다. 직무 상세는 #17·#32·#33·#18 각각 필요한 것만 부른다. Render 512MB·무료 DB에서 요청 수가 곧 지연이다.
  - 저장한 프로필을 기준으로 하면 탐색 결과를 다시 열어도 같은 프로필로 판정된다. 화면이 프로필을 들고 다니지 않아도 된다.
  - 기준일 규칙이 한 클래스에 있으면 체험 시점(7/23·10/14·12/17)끼리 섞이지 않는다. 운영 전환(오늘 기준)도 한 줄로 끝난다.
- 확인
  - `EligibilityApiTest`
    - 본문 없이 부르면 저장한 프로필로 판정한다. 결과는 같은 값을 본문으로 보낸 것과 같다.
    - 행에 `ncs`(#33과 같음)·`views`·`planned`·`planRank`가 있다.
    - 저장한 것도 없으면 404다.
  - `JobApiTest`
    - `views`가 이번 조회까지 센 값이고, 같은 날 다시 열어도 한 번만 센다.
    - `planned`·`planRank`가 있다. `myEligibility`가 #14 행과 같다.
    - 센터와 프로필 없는 학생은 null·false다.
  - `ExploreApiTest`: 카드·탐색을 본문 프로필 없이 만들 수 있고, 프로필이 없으면 404다.
  - `EligibilityOrderTest`: 마감은 마감일 당일부터이거나 모집이 끝난 뒤다.
- 다시 볼 때
  - 프론트가 v2로 옮긴 뒤 2단계(A·B·F, #25 삭제)를 할 때(ADR-0036).
  - 운영 전환 때(모집 판정 기준일을 오늘로).
  - 새 회차가 열려 회차가 둘 이상이 될 때(조회 수·NCS를 회차로 거르는지).
