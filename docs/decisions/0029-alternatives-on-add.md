# ADR-0029 [담기] 바로 뒤에도 빈 자리를 제안한다

- 상태: 확정 (2026-10-07 — 프론트 요청 '[담기]를 누르면 바로 나오게'. API 모양은 이 결정과 같이 제안했고 PR 병합으로 확정한다)
- 문제
  - 빈 자리 제안은 내 지망(S5)에서만 보인다. `POST /api/me/plan/check`가 순위를 정한 지망만 점검하고, 대안의 `why`도 1지망을 기준으로 말한다.
  - 학생은 직무 찾기(S3)·직무 상세(S4)에서 [담기]를 누르는 순간 그 자리를 고른다. 내 지망까지 와서 순위를 정해야 '이미 다른 사람이 정원만큼 담은 자리'라는 걸 알게 된다.
  - 방금 담은 직무는 아직 순위가 없어서 `check`의 `items`에 나오지 않는다. 화면은 그 직무의 관심 신호를 받을 길이 없다.
  - 프론트가 [담기]를 누르면 바로 제안이 나오게 해 달라고 했다(10/7).
- 결정
  - **새 API `POST /api/me/plan/items/{jobId}/alternatives`**(STUDENT, docs/api #27). 본문은 지망 점검과 같다(`{profile, asOf?}`). [담기]가 201·200으로 끝난 바로 뒤에 부른다.
  - 응답 `item` = 그 담은 직무와 신호(순위가 없으면 `rank: null`). 관심은 지망 점검처럼 본인을 뺀 다른 사람 수다(ADR-0019).
  - 응답 `alternatives` = 지망 점검과 같은 규칙·순서·모양(ADR-0016: 지원 가능 · 마감 아님 · 남은 자리 > 0 · 이미 담은 직무 아님, 적합도 → 남은 자리 순 최대 5개). 그 직무도 담은 직무라 빠진다.
  - `why` 앞부분의 '같은 기관' 기준만 1지망 대신 이 직무다 — '방금 담은 직무와 같은 기관의 직무이고'. 나머지('관심 분야와 가깝고' · '지원 조건을 모두 통과했고', 뒤 문장)는 그대로(ADR-0022).
  - **띄울지는 화면이 정한다**: `item.signal.interest ≥ item.signal.headcount`이고 `alternatives`가 있을 때만. 내 지망 카드 안 제안(관심 ≥ 정원인 가장 높은 지망)과 같은 기준이다. 응답에는 몰림 상태·경고 문장이 없고, 화면도 '몰림' 단어를 쓰지 않는다(ADR-0015).
  - 이번 회차에서 담지 않은 직무면 404 `PLAN_ITEM_NOT_FOUND`(담은 직무 기준이라서).
- 이유
  - `check`에 `jobId`를 더하는 방법보다 응답 모양이 갈리지 않는다. 내 지망 화면은 그대로 둔다.
  - 띄울 기준을 서버가 `boolean`으로 주면 ADR-0015에서 없앤 몰림 상태가 다시 생긴다. 신호 숫자만 주고 기준은 내 지망과 같게 화면이 쓴다.
  - [담기] 응답(201·200, 본문 없음)에 붙이지 않는다. 담기는 프로필을 받지 않는데(본문 `{jobId}`), 대안은 판정(지원 가능)이 있어야 고를 수 있다. 프로필은 [저장]+동의 때만 서버에 있다(ADR-0008).
- 확인(2026-2 시드, 예시 프로필, 기준일 7/23)
  - 소서 국내 마케팅(122)을 담으면 관심 2 · 정원 2 → 첫 제안이 같은 기관 해외 마케팅(123, 관심 0) '방금 담은 직무와 같은 기관의 직무이고, 지금 담은 사람이 0명이에요.' 내 지망 시연(1지망 바꾸기)과 같은 자리다.
  - 해외 마케팅(123)을 담으면 관심 0 · 정원 2 → 화면은 제안을 띄우지 않는다.
- 다시 볼 때: 담기마다 판정·적합도를 다시 계산하는 비용이 문제가 되거나(지금은 지망 점검 한 번과 같다), 화면이 제안을 띄우는 기준을 바꿀 때.
