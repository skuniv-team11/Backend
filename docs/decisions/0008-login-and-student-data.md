# ADR-0008 로그인과 체험 계정, 학생 정보 저장

- 상태: 확정 (2026-10-01)
- 결정
  - 이메일 + 비밀번호(해시)로 가입한다. 역할은 `STUDENT`·`CENTER`이고, `CENTER`는 가입으로 만들 수 없다.
  - 가입 없이 누르는 **[예시 프로필로 시작]**(STUDENT)·**[센터 담당자로 보기]**(CENTER)는 체험 계정을 만들어 바로 로그인시킨다. 누를 때마다 따로 생기고 24시간 뒤 계정째 지운다. 체험 계정도 가입 계정과 같은 화면을 쓴다.
  - 토큰은 `Authorization: Bearer` JWT(HS256, `JWT_SECRET`)다. 만료는 가입 계정 7일, 체험 계정 24시간. 쿠키는 쓰지 않는다.
  - 필수로 받는 건 이메일과 비밀번호 해시뿐이다. 프로필(평점·사는 곳 포함)은 `PUT /api/me/profile`에 `consent: true`로 보냈을 때만 저장하고, 탈퇴하면 계정·프로필·담은 지망을 바로 지운다(DB cascade).
  - 프로필 값은 요청 **본문**으로만 보낸다(URL·쿼리 금지). 요청·응답 본문과 프로필 값은 로그에 남기지 않는다.
- 이유
  - 1차 평가(11/2~11/9)는 심사위원이 안내 없이 써 봐야 한다 → 가입 없는 버튼.
  - 모집 중 관심·지원 신호(담은 지망)를 한 사람 한 표로 세려면 계정이 필요하다.
  - 센터 현황판을 `CENTER` 권한으로 막을 수 있다.
  - Vercel과 Render는 사이트가 달라 쿠키는 서드파티 쿠키 차단에 걸린다.
  - 개인정보 부적절 활용 감점(07)을 피하려고 필수 수집을 최소로 둔다.
- 대가: 9/30까지의 '로그인 없음 · 프로필 저장 안 함' 원칙을 바꿨다. 저장 동의·탈퇴 즉시 삭제·로그 금지는 구현 때 테스트로 지킨다.
- 근거 문서: `docs/api/README.md`(인증·권한·개인정보·호출 제한), `V1__init.sql`(`app_user`·`student_profile`·`plan_item`)
- 다시 볼 때: 학교 계정(SSO) 연동을 검토할 때, 공모전 뒤 운영을 이어갈 때.
