# ADR-0018 적합도 추천은 규칙 + 키워드로 한다(임베딩을 쓰지 않는다)

- 상태: 확정 (2026-10-02, E5 결과를 보고 사용자 결정). 처음 0017로 썼다가 같은 날 PM 결정(0016)·현황판 세부(0017)와 번호를 정리해 0018로 옮김
- 결정
  - **추천 점수(#15)** = 5 × 선호 전공 일치(`MATCH`·`OPEN`) + 2 × 관심 키워드 유사도 + 1 × 지원 가능(`ELIGIBLE`) + 0.5 × 지원비 + 0.5 × 채용연계형. 같은 점수면 리스트 순번.
    - 관심 키워드 유사도: 관심 문장 ↔ 직무 텍스트(부서·직무명·직무 개요·교육 목표·요구 역량·주차 계획·기관 업태·종목)의 글자 2~3-gram TF-IDF 코사인을 후보 중 최댓값으로 나눈 0~1. 관심 문장이 없으면 0. 선호 전공 원문은 텍스트에 넣지 않는다(전공은 규칙이 본다).
    - 지원비: 최저임금 대비 75%(법정 하한) → 0, 100% 이상 → 1, 사이는 비례.
    - 선호 전공 가중치(5)가 나머지 합(최대 4)보다 커서 전공이 맞는 직무가 늘 먼저다.
  - **등급(`fit`)**: 선호 전공이 맞고, 관심 문장을 안 적었거나 관심 유사도 ≥ 0.5면 `HIGH`, 아니면 `MEDIUM`. 점수는 응답에 넣지 않는다.
  - **실행 중 임베딩 호출을 하지 않는다.** 실행 중 외부 호출은 Claude(이유 문장)·카카오(통근 — 주소 검색과 대중교통) 둘이다(ADR-0002 개정). `job_embedding` 테이블은 V1에 남지만 채우지 않는다.
  - (10/5) 근거 인용 고르기·기본 문장·비슷한 직무 차이·이유 문장 검증 추가는 [ADR-0020](0020-recommendation-evidence.md)으로 바뀌었다. 점수와 등급은 이 문서 그대로다.
  - **이유 문장(#16)**: 카드에는 규칙 템플릿(`reasonTemplate`)을 바로 주고, Haiku(`claude-haiku-4-5-20251001`)가 쓴 문장은 검증을 통과할 때만 `LLM`으로 준다. LLM에는 학과·학년·관심 문장만 보낸다(평점·사는 곳은 보내지 않음). 검증: 10~200자 · 해요체로 끝남('습니다'·'당신' 없음) · 근거 번호가 준 범위 안 · 따옴표 인용이 근거·직무 원문에 그대로 있음. 하나라도 어기거나 실패·5초 초과·호출 제한이면 `TEMPLATE`. 캐시는 메모리.
  - **지망 점검(#23)의 빈 자리 정렬**도 같은 점수를 쓴다(점수 → 남은 자리 순).
  - 추천·대안에 들어가는 직무(추천은 `INELIGIBLE`·기준일 마감 제외, 대안은 `ELIGIBLE`·마감 아님·남은 자리·담지 않은 직무)와 대안 `why` 문장은 [ADR-0016](0016-demo-profile-and-screen-rules.md)(PM 결정)을 따른다. 이 문서는 점수만 정한다.
- 이유 — E5(2026-10-01, 수기 17건 · 직무 40개 · Hit@5)
  | 방식 | 학과명 질의(보고서 지표) | 실습 내용 질의(진단용) |
  |---|---|---|
  | 무작위 기대 | 29.4% (5.0/17) | 29.4% |
  | 키워드(TF-IDF 글자 2~3-gram) | 35.3% (6/17) | 94.1% (16/17) |
  | 임베딩(Voyage `voyage-4-lite`) | 47.1% (8/17) | 88.2% (15/17) |
  | **규칙(선호 전공 매칭, 동점은 무작위 — 기대값)** | **52.0% (8.8/17)** | — |
  | 규칙 + 키워드 / 규칙 + 임베딩(동점을 유사도로) | 35.3% / 47.1% | — |
  - `pipeline/e5_embedding/README.md`의 판정 기준(키워드보다 뚜렷이 높고 무작위의 2배 = 58.8% 이상)에서 임베딩은 불합격이다. 실습 내용 질의에서는 키워드보다 낮았다.
  - 선호 전공 규칙이 임베딩만큼 맞힌다. 규칙 줄은 수기의 옛 학과명을 지금 학과로 사람이 대응시킨 근사치다(헤어메이크업디자인학과 → 헤어·메이크업디자인, 공연예술학부 → 무대패션·무대기술, 공공인재학부 → 공공인재전공). 표본이 17건이라 방향만 본다.
  - 임베딩을 빼면 Voyage 키·실행 중 호출·실패 대비·직무 임베딩 적재가 모두 필요 없다. 1차 평가 기간(11/2~11/9)에 외부 의존이 하나 줄어든다.
  - AI 활용(평가 25점)의 중심은 문서 구조화(M1, 99.3%)·불일치 탐지(M2)·전공 매핑(M3)·이유 문장이고, 추천 방식은 실험으로 고른 근거를 보고서에 그대로 쓴다.
- 이유 문장 실측(2026-10-02, 이 프롬프트, 예시 학생 상위 5 + 다른 학과 2 = 7건): 검증 통과 7/7, 평균 1.9초 · 최대 2.5초(제한 5초), 7건 합계 입력 9,431 / 출력 844 토큰. 첫 프롬프트에서 '당신'·'~습니다'·별표 강조·'4학년 이상'(원문 '4학년') 같은 문제가 보여 규칙과 검증을 더했다.
- 다시 볼 때: 관심 문장 질의로 정답이 있는 평가 데이터가 생기거나(실제 담기 데이터가 쌓이는 등), 학기마다 직무 수가 크게 늘어 키워드 유사도가 부족해질 때. 그때는 같은 자리(`FitScorer`의 관심 유사도)에 임베딩을 끼운다.
