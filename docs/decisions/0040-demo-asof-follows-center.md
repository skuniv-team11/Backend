# ADR-0040 체험 학생의 진행 기준일은 같은 묶음 센터가 진행한 단계로 따라간다

- 상태: 확정 (2026-10-26 — 박경원 승인: 10/26 점검에서 찾은 '시연 진행 뒤 학생 화면 모순'·'체험 서류 냄 날짜' 고치기. PR 병합으로 확정한다)
- 문제
  - 체험 학생(지원 중 시점)의 진행 기준일은 `demoToday`(7/23)에 고정이다([ADR-0033](0033-internship-flow.md)). 같은 묶음 체험 센터가 시연 버튼(#58)이나 접수·매칭·선발 화면으로 지원서를 진행해도 학생의 내 현장실습(#44)은 7/23 기준이라, 한 화면에 "지원서를 냈어요 · 센터 매칭을 기다려요 · 지원서 마감 D-1"과 "1지망 매칭 · 합격 · 9/1~12/12"가 같이 보였다(10/26 배포 서버에서 확인).
  - 센터 선발 화면은 "합격한 학생은 타임라인이 '협약 · 보험'으로 넘어가요"라고 안내하는데, 체험 학생 화면은 넘어가지 않았다.
  - 마무리 서류 냄 표시(#45)는 실제 시각으로 남아, 실습 마친 뒤 시점(12/17) 체험 학생이 수행결과보고서를 내면 "10/26 냄"이 다른 서류("12/15 냄", 가상)와 섞였다. 지원서 `submittedAt`은 이미 체험 기준일 날짜로 남긴다.
- 결정
  - #44의 기준일: `asOf`를 주면 그날, 가입 계정은 오늘(그대로). 체험 학생은 `demoToday`와 **지원서가 닿은 단계의 날** 중 늦은 날이다(`TimelineService.reached`).
    - 매칭 확정 → 매칭 끝날(MATCH `endsOn`, 7/28)
    - 선발 결과 알림 → 합격은 협약·보험 시작일(CONTRACT `startsOn`, 8/10), 불합격은 면접·선발 끝날(SELECT `endsOn`, 8/5)
    - 합격 뒤 기관 서류(평가표·출근부) 받음 → 종료·제출 시작일(CLOSE `startsOn`, 12/12)
    - 접수만 된 지원서는 날을 옮기지 않는다(아직 신청 기간).
  - #45 냄 시각: 체험 학생은 위 기준일 날짜 + 지금 시각(지원서 낸 시각과 같은 방식), 가입 계정은 지금.
  - 응답 모양은 그대로다. 지원서(#37~#41)의 기준일(신청 기간 판정)은 바꾸지 않는다 — 낸 뒤라 화면에 영향이 없고, 기간 판정은 시점의 날로 두는 것이 맞다.
- 이유
  - 체험은 학생 ↔ 센터를 한 브라우저에서 오가며 보여 주는 시연이다. 센터가 진행한 결과를 학생 화면이 같은 시점으로 보여 줘야 이야기가 이어진다.
  - 실습 중·마친 뒤 시점의 지난 기록(가상)은 단계의 날이 `demoToday`보다 앞이라 바뀌지 않는다.
  - 프론트가 `asOf`를 계산해 보내는 방법도 있지만, 그러면 #45 냄 시각과 홈 화면이 따로 계산해야 한다. 서버 한 곳에서 정한다.
- 남은 것
  - 센터 화면(#46~#57)의 날짜는 실제 오늘 기준이다(가상 지원자 기록도 실제 날짜 근처). 체험 학생이 낸 서류는 센터 마무리 화면에 학생 기준일 날짜로 보인다.
  - 커리어 리포트(#34) `createdAt`은 실제 시각 그대로다.
- 확인
  - `InternshipFlowApiTest`: 매칭 확정 뒤 #44 `asOf` 7/28·`now` MATCH, 합격 알림 뒤 8/10·CONTRACT, `?asOf=2026-07-23`은 그대로, 그때 낸 학점인정신청서 시각이 2026-08-10, 기관 서류를 받은 뒤 12/12·CLOSE.
- 다시 볼 때: 체험 시점·묶음 규칙을 바꿀 때, 센터 화면에 체험 날짜를 쓰기로 할 때.
