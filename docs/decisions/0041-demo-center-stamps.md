# ADR-0041 체험 묶음에서 센터가 처리한 시각은 2026-2 일정의 날로 남긴다

- 상태: 확정 (2026-10-26 — 박경원 승인: 10/26 점검 뒤 남은 것 '지원서 화면 7월 23일 냄 · 10월 26일 접수' 고치기. PR 병합으로 확정한다)
- 문제
  - [ADR-0040](0040-demo-asof-follows-center.md)으로 체험 학생의 진행 기준일은 센터가 진행한 단계를 따라가지만, 센터가 처리한 시각(접수 `receivedAt`·매칭 `matchedAt`·결과 알림 `notifiedAt`·기관 서류 받음·학점 인정 승인 요청·안 낸 학생 알림)은 실제 시각으로 남았다. 그래서 체험 학생 지원서 화면에 "7월 23일 냄 · 10월 26일 접수"처럼 일정 날짜와 실제 날짜가 섞였다.
  - 같은 묶음의 가상 지원자는 낸 날이 7/16~7/22(템플릿)인데 시연 버튼으로 진행하면 "10/26 알림 보냄"이 되어, 센터 화면에서도 두 날짜가 섞였다.
  - 체험 학생 지난 기록(실습 중·마친 뒤 시점)은 이미 일정의 날(매칭 7/28 17시 · 알림 8/5 17시 · 기관 서류 12/16 10시)로 넣고 있었다.
- 결정
  - 체험 묶음(체험 센터 계정의 범위)에서 센터가 처리한 시각은 `DemoTimes`의 일정 날짜로 남긴다. 시연 버튼(#58)과 센터 화면(#48~#56)에서 같다.
    - 접수·보완 요청: 그 지원서를 낸 시각 1분 뒤
    - 매칭(고르기·확정): 7/28 17:00(매칭 끝날)
    - 선발 결과 알림: 8/5 17:00(면접·선발 끝날)
    - 기관 서류(평가표·출근부) 받음 · 학점 인정 승인 요청 · 안 낸 학생 알림: 12/16 10:00(후기 간담회 전날). 가상 지원자의 학생 서류는 그 하루·이틀 전.
  - 체험 학생 기준일(#44)은 기관 서류를 받은 날도 본다(종료·제출 시작일 12/12와 받은 날 중 늦은 날) — 서류 날짜와 기준일이 어긋나지 않게.
  - 가입 센터(묶음 없음)는 지금 시각 그대로다. 응답 모양은 그대로다.
- 이유
  - 체험은 2026-2 일정 위의 이야기다. 학생 화면·센터 화면·지난 기록이 같은 날짜 체계를 쓰면 캡처·시연에서 날짜가 섞이지 않는다.
  - 상수는 지난 기록 템플릿과 같은 곳(`DemoTimes`)에 두어 한 번에 고친다(회차가 바뀌면 템플릿과 같이 바꾼다).
- 남은 것
  - 커리어 리포트(#34) `createdAt`, 면접 일정 입력 시각(`updated_at`)은 실제 시각이다(화면에 날짜로 보이지 않음).
- 확인
  - `InternshipFlowApiTest`: 체험 센터 접수 `receivedAt`이 7월(낸 날), #44 `placement.matchedAt` 2026-07-28 17:00, `notifiedAt` 2026-08-05 17:00, 기관 서류를 받은 뒤 #44 `asOf` 2026-12-16.
- 다시 볼 때: 회차·일정이 바뀔 때(템플릿과 함께), 체험 센터에 기준일을 두기로 할 때.
