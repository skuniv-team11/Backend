# ADR-0038 직무 탐색: AI는 학생 글과 업무의 짝과 그 종류만 찾고, 순서는 규칙이 정한다

- 상태: 확정 (2026-10-11 — 박경원 결정: 순서 규칙에서 선호 전공은 근거 단계 다음, 근거가 없으면 있는 만큼만, 카드가 나온 자리는 규칙이 넣고 AI는 다른 말로 적은 자리를 찾음, '하고 싶은 일' 안에서는 고른 카드가 관심 분야보다 앞, API·DB(V13) 변경 허락. PR 병합으로 확정한다)
- 대체: [ADR-0031](0031-explore-ai.md)의 'AI(Sonnet)가 고른다'·'맞는 정도는 순위로' 부분. 후보는 규칙이 정하고 구절은 서버가 대조한다는 나머지는 그대로다.
- 문제
  - 지금까지는 AI가 후보 중 5곳을 '적합한 순서로' 골랐다. 순서를 정하는 기준이 프롬프트에 없어 "어떤 로직으로 추천하나요?"에 'AI 판단'밖에 답할 수 없었다. 판정·계산은 규칙이 하고 AI는 읽기·연결·설명만 한다는 이 프로젝트의 원칙과도 어긋났다.
  - 배포 서버에서 예시 학생 계정으로 확인한 것(10/11, 4회):
    - 개발 경험(캡스톤 Spring Boot · Docker)을 써도 1·2위가 국내·해외 마케팅 STRONG — 근거 구절이 경험 글이 아니라 예시 프로필의 관심 분야였다.
    - "딱히 해 본 건 없어요"에도 5곳이 STRONG·GOOD으로 찼다. 5위는 "깃허브 이슈를 관리했어요" ↔ "인스타그램 등 SNS 채널 관리".
    - '왜 맞나요'가 "개발 경험은 직접 이어지진 않아요"라고 쓰는데 배지는 STRONG(순위로 붙여서).
    - 카드만 고르면 카드가 나온 자리를 고르고 학생 구절 = 공고 구절(같은 문장)을 근거로 냈다.
- 실험(E9, 프로젝트 문서 'AI-검증-현황', 코드 `pipeline/e7_explore/e9.py` — 서비스 프롬프트 파일을 그대로 읽고 서비스와 같은 구조화 출력·대조·순서 규칙): E7과 같은 47건 · 40자리 · 같은 정답.
  - 1위 / 3위 안 / 5위 안(최종 프롬프트): 실제 수기 17 — 지금(AI 순서) 15 / 15 / 16, 새 방식 15 / 15 / 15. 학생 말투(용어) 14 — 둘 다 14 / 14 / 14. 학생 말투(생활 말) 16 — 둘 다 16 / 16 / 16. 실제 수기 1위에서 한쪽만 맞힌 경우 0 대 0.
  - 자리 순서만 뒤집으면: 지금 13 / 15 / 15 · 12 / 14 / 14 · 15 / 15 / 15, 새 12 / 13 / 14 · 14 / 14 / 14 · 16 / 16 / 16(실제 수기 1위 한쪽만 맞힌 경우 1 대 0, p = 1.00). 1위가 그대로인 경우 지금 32/47 → 새 41/47.
  - 직전 판 프롬프트로 한 번 더 돌린 결과도 실제 수기 1위 15 · 뒤집으면 13이었다 — 실제 수기 17건은 실행마다 1~2건 흔들린다.
  - 같은 단계 안 기준 후보(그 단계 학생 구절 수 · 업무 칸 수 · 짝 수 · 키워드 유사도만)를 같은 원자료로 비교했다. 실제 수기 1위 12~15/17로 모두 지금 방식과 차이가 유의하지 않아(p ≥ 0.25) 가장 단순하게 설명되는 '짝 수'를 골랐다(17건이라 숫자를 맞추려 고른 것으로 보지 않게 비교한 후보를 모두 적어 둔다).
  - 결과 자리 수 중앙값 4, 5곳을 채운 경우 17/47(억지로 채우지 않는다). 응답 중앙값 5.1초(지금 4.9초), 출력 토큰은 비슷하다.
  - 엉뚱한 입력(예시 프로필 후보 23곳, 각 3회): 개발 경험 · 경험 없음 · 지시 무시 · 동아리 회계 → 12회 모두 경험 짝 0곳, 관심 분야로만 맞는 자리만 '관심 분야와 같은 일' 단계로. 예시 학생 실제 글 → 국내·해외 마케팅이 3회 모두 같은 일 1·2위. 편의점 재고·발주 → '능력이 쓰이는 일' 1위가 물류 2회 · AMD 1회. 포토샵·일러스트 → 디자인 1위 3/3, 패키지 디자인 2/3.
- 결정
  - **AI는 짝과 종류만**: 후보 직무 원문과 학생 글을 읽고, 이어지는 자리(최대 10곳)마다 짝 1~5개 `{kind, studentQuote, jobQuote}`와 이유 한 문장을 낸다. 종류는 같은일(해 본 일과 같은 일) · 쓰이는능력(해 본 일에서 실제로 쓴 구체적인 능력이 이 업무에 쓰임 — 성실·소통·협업처럼 어디에나 쓰이는 능력만으로는 잇지 않는다) · 하고싶은일(고른 카드·관심 분야와 같은 일). 이어지는 곳이 없으면 내지 않는다. 순서는 정하지 않는다.
  - **서버가 대조하고 단계를 정한다**(`ExploreVerifier.links`): 후보 안 번호, 학생 구절은 경험·카드·관심 분야 한 조각 안, 직무 구절은 원문 한 칸 안. 학생 구절이 해 본 일에서 왔으면 같은일 → `SAME_TASK`, 쓰이는능력 → `TRANSFER`(하고싶은일이라 하면 어긋난 짝이라 버린다). 카드·관심 분야에서 왔으면 무엇이라 했든 `WISH`. 이유 문장에 강도 표현('바로'·'곧장'·'그대로')이 있거나 규칙을 어기면 단계 문장으로 바꾼다.
  - **고른 카드가 나온 자리는 규칙이 넣는다**: 카드는 그 자리 원문이라 AI가 판단할 일이 없다. 카드가 나온 자리와 그 카드와 거의 같은 글(카드를 합칠 때와 같은 글자 2-gram 자카드 0.8 이상)이 있는 후보 자리에 `WISH`·`CARD` 짝을 넣는다. AI에는 카드 앞에 나온 자리 번호를 붙여 보내고, 카드로는 **같은 일을 다른 회사가 다른 말로 적은 자리**를 찾게 한다 — 경험 글과 같은 '말이 다른 문제'라 AI가 필요한 이유가 같다. 카드만 고른 학생에게도 AI가 쓰인다.
  - **순서 규칙**: ① 근거 단계 — 해 본 일과 같은 일 → 해 본 일의 능력이 쓰이는 일 → 고른 카드와 같은 일 → 관심 분야와 같은 일(이번에 직접 고른 일이 프로필의 관심 분야보다 앞) ② 선호 전공 — 일치 → 가까운 전공 → 전공 무관 → 그 밖(지난 매칭 73명 중 55명이 선호 전공 안이었다. 18명은 밖이어도 매칭돼 막지는 않고 같은 단계 안에서만 앞에 둔다, ADR-0028) ③ 대조를 통과한 짝 수(근거가 많은 자리) ④ 학생 글 ↔ 직무 원문 키워드 유사도(글자 2~3-gram TF-IDF, 판정의 관심 유사도와 같은 방식) ⑤ 리스트 순번. 위에서 5곳까지, 근거가 없는 자리는 넣지 않는다(0~5곳).
  - **맞는 정도 = 근거 단계**: `fit`은 `SAME_TASK` · `TRANSFER` · `WISH`(규칙 추천으로 대신했거나 결과 밖 자리의 '왜 맞나요'는 `NONE`). 순위로 붙이지 않는다. 응답에 근거 출처 `evidence.basis`(`EXPERIENCE` · `CARD` · `INTEREST`)와 통과한 짝 전부 `links`를 더한다.
  - **빈 결과와 실패를 나눈다**: AI가 짝을 하나도 내지 않으면 `source: AI`, `items: []`(이어지는 자리를 못 찾음). AI가 짝을 냈는데 통과한 짝이 없고 고른 카드도 없으면 `VERIFY_FAILED` → 규칙 추천(지금과 같다).
  - V13: `explore_item.fit` 값을 바꾸고 `basis`·`links`(jsonb)를 더한다. 지난 결과(순위로 붙인 STRONG·GOOD)는 새 단계로 옮길 수 없어 지운다 — 다시 탐색하면 된다.
- 이유
  - 순서를 사람이 말로 설명할 수 있다. 심사 질문 "어떤 로직으로 추천하나요?"에 ① 지원 자격은 규칙이 거르고 ② AI는 학생 글과 업무의 짝과 그 종류를 찾고(근거 구절은 코드가 원문과 대조) ③ 순서는 근거 단계 → 전공 → 근거 수 → 글 유사도 규칙이라고 답한다.
  - 정확도는 지금과 같은 수준이고(차이 유의하지 않음) 흔들림은 줄었다. 엉뚱한 입력에 5곳을 억지로 채우지 않는다.
  - AI가 필요한 곳(말이 다른 경험·카드 ↔ 업무의 연결과 그 종류 판단)에만 AI를 쓴다. 순위 정확도만 놓고 보면 임베딩(voyage-4-large)과 차이가 유의하지 않아 'AI가 더 정확하다'고 하지 않는다. AI를 쓰는 까닭은 '이어지지 않는다'는 판단과 근거 짝(학생이 확인할 수 있는 구절)이다.
- 확인
  - `ExploreUnitTest`: 짝의 단계는 학생 구절의 출처로(관심 분야 구절을 같은일이라 해도 WISH, 해 본 일을 하고싶은일이라 하면 버림, 카드 앞 번호를 옮겨 써도 찾음, 같은 짝 하나로, 강도 표현 이유는 버림), 카드 자리 번호는 탐색 때만.
  - `ExploreApiTest`(가짜 AI): 단계 → 짝 수 순서, 두 번 나온 자리는 짝을 합침, 카드가 나온 자리는 규칙 짝, 해요체가 아닌 이유는 단계 문장, AI가 짝을 내지 않으면 빈 결과(규칙 추천 아님), 카드만 고르면 카드 자리 + AI가 찾은 다른 자리, 규칙 추천은 `NONE`·`links` 없음, 결과 밖 '왜 맞나요'는 `NONE`.
  - `check_api_docs.py`: AI 탐색 `fit`은 단계이고 첫 짝과 같음, 짝은 단계 높은 것부터, 해 본 일 짝은 SAME_TASK·TRANSFER · 카드·관심 분야 짝은 WISH, 순서의 첫 기준은 단계, 규칙 추천은 `NONE`.
- 남은 것
  - 짝의 종류(같은 일/능력) 판단 자체는 사람이 매긴 정답과 아직 대조하지 않았다. 팀이 쓴 학생 글 30개(정답은 결과를 보기 전에 다른 사람이)로 '단계가 맞는지'를 잰다.
  - 놓치는 자리가 있다(포토샵·일러스트 ↔ 패키지 디자인 2/3). 3~6위의 단계와 '능력이 쓰이는 일' 같은 경계 판단은 실행마다 달라질 수 있다(결과를 한 번 저장하는 설계라 학생 화면은 바뀌지 않는다).
  - 같은 단계 · 같은 전공 · 같은 짝 수면 키워드 유사도로, 그것도 같으면 리스트 순번으로 갈린다.
- 다시 볼 때: 모델이 바뀔 때(E9 다시), 후보가 크게 늘어 시스템 글이 길어질 때, 팀 정답 세트가 생겼을 때(단계 정확도), 센터 탐색 수요(#24 `demand`)를 단계별로 나눠 보고 싶을 때.
