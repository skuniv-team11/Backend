# ADR-0034 10/10 코드 리뷰 반영: 계정 표시가 든 토큰, 지망 순위 값 그대로, 승인 해시에 학적, 저장하지 않는 개인정보

- 상태: 제안 (2026-10-10 — 박경원 요청: "기존 pr에서도 고칠점이있는지도 봐주고 백엔드 코드도 전체적으로 확인하고 진행". PR 병합으로 확정한다)
- 문제
  - PR #50~#53(쌓인 PR, 미병합)과 백엔드 전체를 리뷰했다(PR #50·#51 · #52 · #53 · 전체 코드, 네 갈래로 나눠 읽음). 높음 3건이 나왔다.
    - DB를 다시 만들면(ADR-0005, 10/15~10/31) `app_user.id`가 1부터 다시 시작한다. 그런데 JWT 비밀키는 그대로라 옛 토큰의 `sub`가 남의 새 계정 id와 맞는다.
    - 1~3지망 순위를 다시 매겨 '2·3지망만 정함'이 1·2지망으로 바뀌고 '1지망 필수' 검사를 통과한다.
    - AI 대신 규칙 추천으로 갈 때 학년·평점·학과가 든 문장이 탐색 결과와 함께 저장된다(동의는 경험 글에 대한 것).
  - 그 밖에는 중간·낮음 문제가 있었다.
    - 승인 해시에 학적이 없다. 그래서 승인받은 뒤 학년을 바꿔도 승인이 유지된다.
    - 센터가 보완 요청 중인 지원서를 바로 접수할 수 있다.
    - 신청 기간이 지난 뒤 보완 요청을 받으면 다시 낼 수 없다.
    - 동시 요청(두 번 누름)에서 500이 난다.
    - 만료됐지만 아직 정리되지 않은 체험 묶음을 쓰면 500이 난다.
    - 가리기에 빈틈이 있다(+82, 띄운 번호, 주민등록번호, 하이픈 학번).
    - 대조를 통과한 구절로 원문이 아니라 AI가 쓴 문자열을 내보낸다.
    - 커리어 리포트를 가릴 때 줄바꿈이 사라져 '한 줄 안' 대조가 무력화된다.
- 결정
  - **토큰에 계정 표시**: 토큰에 `acc`(계정 생성 시각, 마이크로초)를 넣는다. 요청마다 DB의 `created_at`과 맞춰 보고, 다르면 401 `AUTH_REQUIRED`로 막는다. 이 표시가 없는 옛 토큰도 401이라, 배포 뒤 한 번은 다시 로그인해야 한다. JWT 비밀키를 바꾸지 않아도 DB를 다시 만들면 옛 토큰이 막힌다.
  - **지망 순위는 값 그대로**: 지원서·승인 화면·센터 매칭은 담은 직무 순위(#22)의 값을 그대로 쓴다. 2·3지망만 정했으면 `rank`도 2·3이고, 1지망이 없으면 `PICKS` 검사가 false다. #22에서 빈 순위를 막는 방법도 있었지만 API 동작이 바뀌어 택하지 않았다. 매칭(#50)의 `rank`는 그 지원서에 있는 순위 값만 받는다.
  - **승인 해시에 순위 값·학적**: 해시는 신청서·이력서·자기소개서·서약·동의·서명에 1~3지망의 (순위, 직무)와 학적(학과·학년·이수 학기·평점·졸업예정)을 더해 만든다. 학적은 내기 전이면 저장한 프로필, 낸 뒤면 고정한 값이다. 학생 화면·승인 화면·센터 화면·타임라인이 한 함수(`ApplicationService.basis`)로 같은 값을 만든다. 승인 화면도 같은 학적을 보여 준다.
  - **센터 상태 바꾸기**: 접수(`RECEIVED`)는 새로 들어온(`SUBMITTED`) 지원서만 한다. 보완 요청 중이면 409이고, 학생이 고쳐 다시 내야 접수할 수 있다. 보완 요청을 받은 지원서는 신청 기간이 끝났어도 다시 낸다. 이때 처음 낸 날 열려 있던 지망은 그대로 낼 수 있다. 센터의 보완 요청에 날짜 제한이 없어서다.
  - **낸 지원서의 마감 표시는 낸 날 기준**: 체험 학생의 `submittedAt`은 기준일 날짜로 남긴다(시연 속 날짜와 같게).
  - **지원서 승인 링크는 매칭 확정 뒤 404**: 링크(메신저로 전해짐)로 이름·학번이 계속 열리지 않게 한다.
  - **저장하지 않는 개인정보**: 규칙 추천으로 대신할 때 `reason`은 기본 문장 "지원 조건과 적합도 점수로 고른 자리예요."로 저장한다. DB 오류 메시지에는 행 값을 싣지 않는다(`logServerErrorDetail=false`).
  - **가리기를 넓힌다**: 가리는 범위는 다음과 같다.
    - 전화: +82, 띄어 쓰거나 줄표를 바꾼 번호
    - 주민등록번호 꼴
    - 하이픈 학번
    - NUL 문자는 지운다. 그 밖의 글에 NUL이 있으면 400이다.
  - 커리어 리포트는 줄마다 가리고 줄바꿈을 남긴다.
  - **대조 결과는 원문 구간**: 대조를 통과한 구절은 원문에서 맞은 구간을 잘라 돌려준다. 대조 열쇠의 최소 길이는 6자다.
  - **같은 계정의 겹친 요청은 차례로 처리한다**
    - 탐색·커리어 리포트를 바꿀 때 계정 행을 잠근다(`FOR NO KEY UPDATE`).
    - 지원서는 행을 잠그고, 첫 저장은 `ON CONFLICT`로 처리한다.
    - 접수번호를 매길 때 범위마다 트랜잭션 잠금을 건다.
    - 상태를 바꾸는 UPDATE에는 상태 조건을 붙인다.
    - 만료된 체험 묶음은 Clock 기준으로 먼저 지우고 새로 만든다.
  - **시드 안전장치**
    - 지원서가 쓰는 학과는 지우지 않는다.
    - 직무마다 NCS 세분류가 하나씩 없으면 `to_sql.py`가 멈춘다.
    - 체험 템플릿의 직무가 시드에서 빠졌으면 건너뛴다.
    - 표기 차이 판정은 뜻을 바꾸는 말(불·미·없음·있음·오전·오후 등)이나 목록 표시의 수가 다르면 표기 차이로 보지 않는다.
    - 실습기간 연도 오타는 고친 뒤 리스트와 비교한다. 2026-2 시드의 결과는 바뀌지 않는다(알림 6건 그대로, 표기만 다른 문서 내부 불일치 2건도 그대로).
- 이유
  - 개인정보·권한 문제(토큰, 저장 문장, 승인 링크)는 심사(11/2~11/9) 전에 막아야 한다. 감점 07에 걸린다.
  - 학생이 2·3지망으로 정한 것을 서버가 1·2지망으로 바꿔 내면 학과(부)장 화면과 실제 지망이 어긋난다. 실제 순위 값을 쓰면 계약 모양은 그대로다.
  - 승인은 '학과장이 본 것 = 낸 것'을 지키는 장치다. 학적도 보고 승인하므로 학적도 해시에 넣는다.
