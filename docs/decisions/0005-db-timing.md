# ADR-0005 배포 DB는 Render 무료 Postgres — 지금 만들고 10/15~10/31에 한 번 다시 만든다

- 상태: 확정 (2026-09-30), **개정 (2026-10-02)**
- 결정 (10/2 개정)
  - 프론트는 로컬이 아니라 배포(Vercel 운영·미리보기 주소)로 테스트한다(10/2 사용자 결정). 그래서 배포 백엔드에 **지금** DB가 있어야 한다. Render 무료 Postgres를 10/2에 만든다(지역 singapore, Postgres 18).
  - 무료 DB는 만든 날 + 30일에 만료된다(10/2에 만들면 11/1 — 제출일). 만료 뒤 14일 안에 유료로 올리지 않으면 삭제된다. **10/15~10/31 사이에 지우고 새로 만들어** 만료를 11/12 발표 뒤로 넘긴다(10/15에 만들면 11/14 만료). 워크스페이스당 무료 DB는 1개라 기존 것을 먼저 지운다.
  - 다시 만들면 사라지는 것: 가입 계정, 저장한 프로필, 담은 지망(체험 계정은 원래 24시간 뒤 삭제). 기관·직무·근거·수기·리플레이 신호는 `R__seed.sql`(ADR-0014), 시연용 예시 프로필은 `application.yml`의 `app.example-profile`(ADR-0016)이라 그대로 돌아온다.
  - 웹 서비스는 10/2부터 Starter(`plan: 0.5c-512mb`, $7/월)로 둔다. Free는 15분 동안 요청이 없으면 잠들어 첫 요청이 1분 넘게 걸리는데, 배포로 테스트하면 이게 매번 걸린다. 11/12 발표 뒤 `render.yaml`에서 `free`로 내린다.
- 처음 결정 (9/30): 10/15 이후에 만든다(30일 뒤 만료 → 11/14까지). 그 전은 로컬 Postgres 18(docker compose).
- 이유
  - 11/2~11/9 1차 평가(공개 링크)와 11/12 최종 발표까지 살아 있어야 한다.
  - 무료 DB는 백업이 없고 만료가 있어 언제든 다시 만들 수 있어야 한다. 스키마는 Flyway, 데이터는 시드라 새 DB에 앱이 뜨면 그대로 채워진다.
  - 유료 DB(`0.1c-256mb`, $6/월 + 저장 용량)는 재생성 한 번을 피하는 값밖에 없어 쓰지 않는다. 돈은 잠들지 않는 웹 서비스에 쓴다.
- 결과
  - `render.yaml`에 `DB_URL`·`DB_USER`·`DB_PASSWORD`(`sync: false`)를 두어 Blueprint를 만들 때 함께 넣는다. 다시 만들 때는 대시보드 Environment에서 세 값을 바꾸고 다시 배포한다(README 'DB').
  - 비용(초 단위 일할): Starter 10/2~11/12 약 $9.6. DB 0원.
  - 로컬에서는 서버를 띄우지 않는다(10/2). 테스트는 CI의 Testcontainers(ADR-0010)로 돈다.
- 다시 볼 때: 발표 이후 운영을 이어갈 때(유료 DB 전환).
