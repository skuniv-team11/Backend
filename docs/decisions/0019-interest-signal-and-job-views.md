# ADR-0019 모집 신호는 '관심'(내 지망에 담은 사람) 하나 · 실제 담은 수를 더함 · 직무 조회수 · 기준일 7/23

- 상태: 확정 (2026-10-05, 조장)
- 결정
  - **관심 = 내 지망에 담은 사람 수**다. 순위와 상관없이 [담기]한 사람을 1인 1표로 센다. 모집 신호는 이 숫자 하나다.
    - 예전의 '지원 의사'(`intent`)는 '관심'(`interest`)으로 이름을 바꾸고, 예전의 '관심'(근거 없는 가상 여분, 항상 지원 의사 이상)은 없앤다. 두 숫자가 헷갈려서다.
    - API `Signal`: `intent` → `interest`, 새 필드 `liveInterest`. 현황판 요약: `intentTotal` → `interestTotal`, 새 필드 `liveInterestTotal`. `zeroSignalJobs`는 이름 그대로, 관심이 0인 직무 수.
    - DB(V3): `replay_signal.interest_count`(예전 관심)를 지우고 `intent_count`를 `interest_count`로 바꾼다. 시드 생성기(`replay.py`)도 관심 하나만 만든다 — 날짜는 10/5 전 지원 의사와 같다(난수를 같은 순서로 뽑는다). 리플레이 신호 90행 → 21행.
    - 지망 대안 `why`의 뒤 문장: '지금 지원 의사가 0명이에요.' → '지금 담은 사람이 0명이에요.'
  - **리플레이 가상 값에 실제 사용자가 담은 수를 더한다.**
    - 실제 값 = 지금 그 직무를 담아 둔 계정 수(`plan_item`). 체험 계정도 센다(심사위원도 체험 계정으로 들어온다). 체험 계정 수명은 24시간 그대로라, 계정이 지워지면 그 수도 빠진다.
    - 실제 값은 시연 속 '오늘'인 기준일(`replay.defaultAsOf`)에 생긴 관심으로 본다. 현황판 슬라이더로 기준일보다 앞 날짜를 보면 가상 값만 나온다. 기준일에 이미 마감(`closesOn` ≤ 기준일)인 직무에는 더하지 않는다.
    - 지망 점검(#23)은 본인이 담은 것을 빼고 다른 사람 수만 보여 준다(남은 자리 = 정원 − 다른 사람 관심). 현황판(#24)은 모두 센다.
    - 정원 도달 예상일도 실제 값이 들어간 최근 3일 추세로 계산한다.
  - **직무 조회수**(#25 `GET /api/jobs/{jobId}/views` → `{jobId, views, todayViews}`, 로그인).
    - 학생이 직무 상세(#17)를 열면 계정마다 직무별로 하루(한국 시간) 한 번 센다. 센터 담당자는 세지 않는다. 실제 값만 둔다(가상 조회수 없음 — 맞출 실제 값이 없어 지어낸 숫자가 된다).
    - DB(V3) `job_view(job_id, user_id, viewed_on)`, 같은 계정·직무·날은 한 행(UNIQUE). 계정이 지워지면 `user_id`만 NULL — 조회수는 남고 누가 봤는지는 남지 않는다.
    - 조회 기록이 실패해도 직무 상세는 그대로 준다.
  - **시연 기준일 7/18 → 7/23**(`app.replay.default-as-of`, 환경변수 `REPLAY_DEFAULT_AS_OF`).
- 이유
  - 학생이 [담기]·순위로 하는 일은 '지원'이 아니라 관심 표시다. '지원 의사'라고 부르면 과장이고, 지원 의사·관심 두 숫자를 같이 보이면 무엇을 뜻하는지 설명하기 어렵다. 예전 관심은 생성기가 지원 의사 위에 여분을 얹은 값이라 근거가 없었고 계산에도 쓰이지 않았다.
  - 평가 기간에 실제로 써 본 사람이 담으면 숫자가 움직여야 '다른 학생이 몇 명 담았는지'를 보여 줄 수 있다. 가상 값만 두면 담아도 아무것도 바뀌지 않는다.
  - 7/23(모집 마지막 전날) 실측(10/5, 실제 담은 수 없을 때): 관심 합 18 · 관심 0 직무 30 · 마감 1(101) · 정원 이상 9직무. 시연 흐름(1지망 국내 마케팅 2/2 → 같은 기관 해외 마케팅 0/2 대안)은 그대로다. 7/18과 달리 정원 도달 예상일이 보이는 직무는 없다(AMD·스미스가 이미 정원에 닿음).
- 결과
  - `docs/api`(README·예시 JSON·새 `job-views.json`)와 Swagger 계약 스펙(25개), `scripts/check_api_docs.py`·`build_openapi.py`, `CodeLabels`(`signalSource` `REPLAY` 표기)를 같이 고쳤다. 테이블 22개.
  - ADR-0008·0009·0014·0015·0016·0017·0018의 '지원 의사' 표현을 '관심'으로 맞췄다.
  - **프론트가 바꿀 것**: `signal.intent` → `signal.interest`(예전 `signal.interest` 표시는 지운다), `summary.intentTotal` → `summary.interestTotal`, 화면 문구 '지원 의사' → '관심'. 조회수는 #25를 따로 부른다. 필요하면 `liveInterest`로 '실제 N명'을 보여 줄 수 있다.
- 다시 볼 때: 실제 지원(센터 접수) 데이터를 받게 되거나, 리플레이를 끄고 운영(오늘 날짜·실제 값만)으로 바꿀 때.
