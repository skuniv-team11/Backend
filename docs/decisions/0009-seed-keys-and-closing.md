# ADR-0009 시드 기본키와 모집마감·몰림 정의

- 상태: 확정 (2026-10-01). 몰림 정의는 [ADR-0015](0015-no-crowded-status.md)로 대체(10/1 회의 — 몰림 표시·경고를 하지 않는다)
- 결정
  - **시드 테이블의 기본키는 시드가 정한다**(자동 증가 없음). 실행 중에 행이 생기는 `app_user`만 자동 증가이고, `student_profile`·`plan_item`은 그 id를 키로 쓴다.
  - **모집마감**은 `job.closes_on` + `close_reason`이다. `APPLICATION_DEADLINE` = 운영계획서 접수마감일자, `CENTER_CLOSED` = 센터 참여기관 리스트의 모집마감 표시. 둘 다 있으면 이른 날짜를 쓴다. `CENTER_CLOSED`인데 날짜 기록이 없으면 리플레이 생성기가 날짜를 정하고 `closes_on_is_virtual = true`로 둔다(화면에 가상 표시).
  - 기준 날짜(asOf)가 회차 종료일 뒤이거나 `closes_on` ≤ asOf면 마감이다.
  - **몰림은 마감이 아니다.** 지원 의사가 정원 이상이면 경고만 하고 지원은 막지 않는다. 빈 자리 제안은 남은 자리가 있는 직무만 고르므로 마감·몰린 직무는 자연히 빠진다.
  - 추세로 본 시점은 '정원 도달 예상일'이라 부른다. '마감'은 모집마감만 뜻한다.
  - 선착순은 따로 모델링하지 않는다(센터 확인 항목).
- 이유
  - 다시 시드해도 `/jobs/:id` 주소와 학생이 담아 둔 지망이 같은 행을 가리켜야 한다.
  - 마감과 몰림을 섞으면 학생이 몰린 자리를 '지원 불가'로 오해한다. 기획안은 몰림을 경고와 대안 제안으로만 다룬다.
  - 날짜를 만든 마감과 실제 마감을 구분하지 않으면 시연에서 가상 값을 사실처럼 보여 주게 된다.
- 근거 문서: `V1__init.sql`(맨 위 원칙 주석, `job.closes_on*`), `docs/api/README.md`(지망 `check` 규칙)
- 다시 볼 때: 센터가 선착순·모집마감 표기 방식을 알려 줄 때, 다른 사업·대학으로 넓힐 때.
