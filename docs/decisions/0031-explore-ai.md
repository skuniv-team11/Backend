# ADR-0031 직무 탐색: 지원 조건은 규칙이 거르고, 경험과 이어지는 자리는 AI(Sonnet)가 고르고, 서버가 근거를 대조한다

- 상태: 확정 (2026-10-10 — 박경원 결정: 새 API 설계안 'P0부터'. PR 병합으로 확정한다)
- 문제
  - 학생이 쓴 경험(동아리·아르바이트)과 공고의 업무 문장은 쓰는 말이 달라 키워드 추천(#15, ADR-0018)으로는 이어지는 자리를 못 찾는다. 예: "동아리 회비 장부 · 결산" → 회계업무지원이 키워드 14위.
  - 그렇다고 AI가 지원 자격을 판단하거나 원문에 없는 말을 지어내면 안 된다(AGENTS.md '검증 없이 내보내지 않는다').
- 실험(E7, 프로젝트 문서 'E7-AI-필요성-실험', 코드 `pipeline/e7_explore`): 실제 수기 17건 · 가상 경험 30개로 키워드 · AI 바꾸기 → 키워드 · AI 판단을 비교했다.
  - AI 판단(Sonnet)이 실제 수기 Hit@3 13 → 15/17, 생활 말 Hit@1 10 → 15~16/16으로 키워드보다 낫다. AI가 경험을 공고 말로 바꾸기만 하는 설계는 키워드와 거의 같다('억지 AI').
  - Haiku는 Hit@1이 키워드보다 낮고 공고 구절 일치도 낮다(170/235) → Sonnet급이어야 한다.
  - 같은 입력도 실행마다 순위가 조금 달라진다 → 한 번 만들어 저장한다.
- 결정
  - **후보는 규칙이 정한다**: 판정(#14) ELIGIBLE·NEEDS_CHECK이고 기준일에 마감되지 않은 직무만. 지원 불가·마감 직무는 카드·AI 입력·결과·'왜 맞나요' 어디에도 없다. 후보가 0이면 AI를 부르지 않고 막은 조건(#15 blockedBy)을 준다.
  - **AI(Sonnet)가 고른다**: 후보 직무 원문(부서·직무명·개요·교육 목표·요구 역량·주차 계획)과 학생 글(해 본 일 0~3개 · 고른 '하고 싶은 일' 카드 0~5개 · 관심 분야)을 함께 읽고 5곳과 학생 구절 · 공고 구절 · 이유 한 문장을 낸다. 구조화 출력, 생각 단계 없음(`between_tools`), 시스템 글은 프롬프트 캐시. 학과·학년·평점·자격증·사는 곳은 보내지 않는다(학과에서 능력을 추론하지 않게).
  - **서버가 대조한다**(`ExploreVerifier`): 후보 안의 번호, 구절이 원문 한 조각(학생 글 한 줄 · 직무 원문 한 칸) 안에 그대로 있음, 해요체·'습니다'·'당신'·'선호 전공' 없음. 통과한 것만 쓰고, 0곳이면 규칙 추천으로 대신한다.
  - **맞는 정도는 순위로**: 1~2위 STRONG, 3~5위 GOOD, 결과 밖 자리의 '왜 맞나요'는 WEAK(덜 이어지는 까닭도 쓰게 한다). E7에서 AI가 덜 맞는 자리에도 이유를 붙였기 때문이다.
  - **'왜 맞나요'**: 1~3위는 탐색 때 동시에 만들어 저장하고, 나머지는 직무 상세에서 처음 열 때 만든다. 학생이 한 일 → 이 자리의 일 → 왜 도움(points) · 새로 해 볼 일 · 미리 채울 것. 구절은 같은 방식으로 대조한다.
  - **'하고 싶은 일' 카드**: 후보 직무의 개요 항목(모자라면 주차 계획 항목)을 원문 그대로 짧게, 배우는 것·목표 항목(이해·교육·소개)은 빼고 기관 이름은 '회사'로 가린다. 거의 같은 글은 하나로. 경험 글을 쓰기 어려운 학생의 입력 재료다.
  - **대신하기**: 키 없음 · 호출 한도(계정당 1시간 10회 · IP당 60회 · 서버 하루 300회) · 실패·30초 초과 · 대조 0곳이면 200 + 적합도 추천(#15, `source: RULE`). 화면이 깨지지 않는다.
  - **개인정보**: 경험 글은 `consent: true`일 때만 받는다. 전화번호·이메일·8~10자리 숫자는 가린 뒤 AI에 보내고 저장한다. 계정당 마지막 1건만 두고 지우기(#31)·탈퇴·체험 계정 정리 때 함께 지운다. 다시 볼 때 저장한 프로필이 있으면 그 프로필로 다시 판정해 지원 불가가 된 자리를 숨긴다(학과·학년·평점은 탐색 결과에 두지 않는다).
  - V9 `explore_run`·`explore_item`·`explore_why`. 프롬프트는 `prompts/explore-rank-system.md`·`explore-why-system.md`(E7 demo의 규칙을 구조화 출력·해요체로 옮김).
- 이유
  - AI가 필요한 곳(말이 다른 경험 ↔ 업무 연결)에만 AI를 쓰고, 틀리면 안 되는 곳(지원 자격)은 규칙이, 지어내면 안 되는 곳(근거)은 코드가 맡는다.
  - 순위를 저장하면 같은 학생이 다시 열어도 결과가 바뀌지 않고, 센터는 직무별 탐색 수요를 셀 수 있다(PR4 현황판).
- 확인
  - `ExploreApiTest`(가짜 AI): 후보 밖 번호·지어낸 구절·해라체·중복 직무를 버림, 순위로 fit, 1~3위 설명 저장, 다시 판정해 숨김, 대신하기 4가지, 한도, 동의·입력 검사.
  - 실제 API(10/10, `ExploreLiveCheck`와 같은 입력): 순서 6.3초 · 5곳 모두 대조 통과, '왜 맞나요' 3곳 5.9~7.1초 · 구절 모두 통과. 순서 호출의 시스템 글 11,621토큰을 캐시에 썼다.
  - 비용(E7 실측): 탐색 순서 약 $0.010, '왜 맞나요' 한 곳 약 $0.011 → 탐색 1번 약 $0.04. 하루 300회 한도면 최대 약 $12.
- 남은 것: S2 가상 세트는 Claude가 쓴 것이라 팀이 경험 30개를 다시 써서 잰다. 선호 전공을 AI 순서에 보정할지는 정하지 않았다(지금은 참고 표시만).
- 다시 볼 때: 모델이 바뀔 때(E7 다시), 후보가 크게 늘어 시스템 글이 길어질 때(나눠 부르기), 탐색 수요를 센터에 보여 줄 때(PR4).
