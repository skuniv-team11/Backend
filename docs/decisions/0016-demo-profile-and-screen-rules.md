# ADR-0016 시연 기준 예시 프로필과 판정·대안·현황판 규칙

- 상태: 확정 (2026-10-02, PM)
- 결정
  - **예시 프로필은 지금 값 그대로 둔다.** `application.yml`의 `app.example-profile`: 메이크업디자인학과 3학년 · 이수 5학기 · 평점 3.4 · 졸업 예정 아님 · 관심 '뷰티 브랜드 SNS 마케팅' · 사는 곳 노원구(11350).
  - **리플레이 기준일 기본값은 7/23이다**(`rounds/current`의 `replay.defaultAsOf`, 10/5 7/18에서 바꿈 — ADR-0019). 그날도 마감은 101 AE(센터 모집마감) 하나라 현황판에 '마감 1'이 실제 값으로 나온다.
  - 화면 규칙(`docs/api/README.md`에 적었다)
    1. 판정: 검토 알림의 `fieldKey`가 판정 항목(`gradeRequirement`·`gpaRequirement`·`portfolio`·`certificate`)이면 그 항목 행이 `CHECK`가 되고 `alertId`가 붙는다. 그 밖의 알림은 판정을 바꾸지 않고 학생 목록에 '문서 검토' 꼬리표만 단다.
    2. 판정 행에 `closing`(직무 상세와 같은 마감 값)과 `alertCount`(그 직무에 걸린 알림 수, 기관 단위 알림은 세지 않음)를 더한다. 목록은 `closesOn` ≤ 기준일이면 '마감' 꼬리표를 단다.
    3. 추천: `INELIGIBLE`과 기준일에 마감된 직무를 뺀 직무 중 적합도 점수 상위 5개. 점수는 응답에 넣지 않는다.
    4. 직무 상세 `requirements.majorAliases`: 선호 전공 표기마다 확정된 학과 대응. '선호 전공 안내'와 판정 이유의 '표기 해석'에 쓴다.
    5. 지망 대안: `ELIGIBLE` · `CLOSED` 아님 · 남은 자리 > 0 · 이미 담은 직무 아님. 적합도 점수 → 남은 자리 순 최대 5개. `why`는 규칙 문장이다.
    6. 현황판 위험: `NARROW_POOL` = 적격 학생 풀 200명 미만, `DOC_ALERT` = 그 직무 또는 그 기관에 검토 알림이 있음.
    7. `closesOn`은 '이 날부터 지원 불가'다. 화면은 하루 전 날짜를 마감일로 보여 준다(7/18 → '7/17 마감').
    8. 코드 묶음 `ntsStatus`(`ACTIVE` 계속사업자 · `SUSPENDED` 휴업자 · `CLOSED` 폐업자)를 `GET /api/codes`에 더한다.
- 이유
  - 2026-2 실제 시드로 예시 프로필을 계산하면 40직무 중 지원 가능 23 · 확인 필요 17 · 지원 불가 0이다. 확인 필요 사유가 학년(4학년만 7)·졸업예정자(7)·학점 하한(3.5 4개, 3.6 1개)·포트폴리오(3)로 다 나온다.
  - 선호 전공 표기 '미용예술대학'·'미용예술계열'이 메이크업디자인학과로 해석되는 직무가 4개(소서 AMD·국내 마케팅·해외 마케팅, 비욘드마케팅그룹)라 M3(표기 해석)를 보여 줄 수 있다. 나머지 36개는 '선호 전공 밖이어도 지원 가능'(문제 ②)을 보여 준다.
  - 관심 문장으로 추천 1·2위가 소서(화장품) 국내·해외 마케팅이고, 소서는 선배 수기가 4건이다.
  - 기준일 7/23에 1지망 국내 마케팅이 관심 2/정원 2, 같은 기관 해외 마케팅이 0/2라 빈 자리 제안 → 1지망 바꾸기 시연이 실제 값으로 된다(관심 = 내 지망에 담은 사람, ADR-0019).
  - 비교한 대안
    - 광고홍보콘텐츠학과: 전공 표기와 학과 이름이 똑같아 표기 해석 시연이 안 된다.
    - 경영학부: 대부분 직무에 걸려 '선호 전공 밖' 시연이 약하다.
    - 4학년: 학년 확인 필요가 사라진다.
  - `NARROW_POOL` 200명은 2026-2 시드의 적격 풀 분포(98·102·102·102·102·115·115·198명 …)에서 하위 직무를 가르는 값이다(10/2 결정).
- 결과
  - `docs/api`(README·예시 JSON)와 Swagger 계약 스펙, `CodeLabels`를 같이 고쳤다. DB 스키마는 그대로다.
  - 예시 `eligibility.json`의 103(웹 서비스 개발)에서 '선호 전공 표기' `CHECK` 행을 뺐다. `majorRequirement` 알림은 판정을 바꾸지 않는다. 103은 학년이 `NOT_MET`이라 그대로 `NEEDS_CHECK`다.
  - V1 `review_alert.field_key` 주석의 예시(`majorRequirement`)는 이 결정과 다르다. 적용한 마이그레이션은 고치지 않으므로(ADR-0010) 이 ADR과 `docs/api/README.md`를 따른다.
  - 프론트: 판정 행의 `closing`·`alertCount`, 직무 상세의 `requirements.majorAliases`, 코드 `ntsStatus`가 새로 생긴다.
  - 사는 곳 목록(`area`)은 10/2 행정표준코드로 시드했다(83곳). 예시 프로필의 사는 곳은 노원구(11350)로 들어가고, 통근은 카카오 주소 검색으로 그때 계산한다(ADR-0007 개정).
- 다시 볼 때: 시드가 바뀌거나(새 회차) E5 임베딩 결과로 추천 순서가 크게 달라질 때.
