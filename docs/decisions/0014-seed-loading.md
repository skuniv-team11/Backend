# ADR-0014 시드는 seed.json → Flyway 반복 마이그레이션(R__seed.sql)으로 넣는다

- 상태: 확정 (2026-10-01)
- 결정
  - **적재 방식**: `pipeline/seed/build_seed.py`가 원본·추출 결과를 합쳐 `pipeline/seed/seed.json`(테이블별 행)을 만들고, `to_sql.py`가 그걸 `src/main/resources/db/migration/R__seed.sql`로 바꾼다. 둘 다 커밋한다. Flyway는 이 파일의 checksum이 바뀌면 `V*` 다음에 한 트랜잭션으로 다시 적용한다. 앱 코드에 시드 적재 기능은 없다.
  - **다시 시드해도 사용자 데이터가 같은 행을 가리키게**(ADR-0009):
    - 부모 테이블(`program`·`recruit_round`·`department`·`institution`·`workplace`·`job`)은 id로 upsert, seed에 없는 행만 지운다. 직무가 지워지면 담아 둔 지망도 cascade로 지워진다. 학생 프로필이 쓰는 학과는 seed에서 빠져도 남긴다.
    - 이름·순번 같은 유니크 열은 upsert 전에 잠시 비켜 둔다(행끼리 이름·순번이 바뀌어도 부딪히지 않게).
    - 자식 테이블(근거·알림·수기·신호·전공 표기·주차 계획)은 통째로 지우고 다시 넣는다. 사용자 데이터가 가리키지 않는다.
    - `area`·`job_embedding`·`round_result`는 건드리지 않는다(각각 좌표 대기, E5, 센터 동의 뒤 로컬 적재).
  - **시드 id 등록부** `pipeline/seed/curated/ids.json`: 기관·직무·근로지의 자연 키 → id. 한 번 준 id는 바꾸지 않는다. 기관 1부터, 직무 101부터(리스트 순번 `list_seq`와 헷갈리지 않게).
  - **값의 기준**: 정원·지원비·기간·요일·시간·학년·학점·선호 전공·근로지·모집마감 표시는 참여기관 리스트, 나머지와 근거는 운영계획서 추출. 두 문서 값이 다르면 `LIST_MISMATCH` 알림(계획서 값이 '선호·무관'처럼 불확실하면 비교하지 않음). 자세한 표는 `pipeline/seed/README.md`.
  - **`closes_on`** = 이 날부터 지원 불가. 마감 시각이 그날 안이면 다음 날, '0시'면 그날.
  - **학과**: 교육통계 2025-10-01 72행 중 재학생이 있는 60개만(재학생 0은 폐지·통합 단위).
  - **전공 표기 → 학과**: 표기 25종은 모두 넣고, 학과 연결은 사람이 확정한 것(`EXACT`·`CONFIRMED`)만. Claude 초안(`DRAFT`)은 적재하지 않는다(V1 `major_alias` 주석 'M3 — 사람이 확정한 매핑만').
  - **리플레이 신호**: 직무별 지원 의사 합 = 최종 배정 수, 날짜는 시드 고정 난수(`replay.py`). 관심 누적 ≥ 지원 의사 누적, 마감일부터는 행 없음.
  - **검사**: `check_pipeline.py`가 단위 테스트와 `to_sql.py --check`, 백엔드 `SeedFileTest`가 SQL 머리글의 해시(seed.json·본문), `SeedTest`가 적용 결과(18·40·59·21·17과 리플레이 규칙)를 본다. 두 파일은 `.gitattributes`로 LF 고정.
- 이유
  - Render 무료 DB는 백업이 없고 11/14에 만료된다(ADR-0005). 앱이 뜨기만 하면 같은 시드가 들어가야 한다 — 따로 돌리는 적재 스크립트는 빠뜨리기 쉽다.
  - `V2__seed.sql`처럼 버전 마이그레이션으로 넣으면 고칠 때마다 새 번호가 필요하다. 참여기관 리스트는 '상시 업데이트'라 시드가 자주 바뀐다.
  - 통째로 지우고 다시 넣으면 학생이 담아 둔 지망(`plan_item`)과 프로필(`student_profile`)이 FK로 지워지거나 막힌다. 그래서 사용자 데이터가 가리키는 테이블만 upsert로 다룬다.
  - seed.json을 같이 커밋하면 리뷰는 JSON diff로 하고, SQL은 그 함수라 손으로 고친 흔적이 검사에 걸린다.
- 결과
  - 시드를 바꾸면 다음 배포에서 자동으로 반영된다. 직무가 빠지면 그 직무를 담은 지망이 사라진다(의도).
  - 테스트 DB(Testcontainers)에도 실제 시드가 들어간다. 테스트에서 '시드 전' 상태가 필요하면 행을 지우지 말고 잠시 이름을 바꾼다(`AuthApiTest`).
  - 시드 파일은 약 220KB, 적재는 1초 안쪽이다.
- 다시 볼 때: 다른 회차·사업을 더할 때(지금은 seed가 전체 데이터라 회차를 추가해도 같은 seed.json에 넣는다), 시드가 커져 기동이 느려질 때, 센터가 데이터를 직접 올리게 될 때(관리 화면).
