# ADR-0030 소개서 사진을 보여 주고, 선배 수기는 전문을 넣고, 표기만 다른 검토 알림은 만들지 않는다

- 상태: 확정 (2026-10-10 — 박경원 결정: '소개서 사진 전부', '수기는 그냥 전부', '살짝 글씨가 다르거나 오타는 문서 검토에 띄울 이유가 없다'. PR 병합으로 확정한다)
- 문제
  - 직무 상세에 회사가 어떤 곳인지 보여 줄 그림이 로고뿐이다. 실습기관 소개서(별지 제1-2호)에는 '회사 전경 및 활동사진' 칸이 있고 캡션까지 달려 있는데 하나도 쓰지 않았다. 서식에는 '현장실습학기제 홍보자료로 사용될 수 있습니다'라고 적혀 있다.
  - 선배 수기는 실습 내용과 실습 결과의 사실 구절(0~3개)만 넣었다(ADR-0020). '우수' 수기라 긍정 쪽으로 치우쳐서였는데, 학생이 수기를 읽을 수 없어 한 줄 소개·회사 소개·실습 결과·소감이 모두 빠졌다.
  - 검토 알림 12건 중 6건이 학생·센터가 챙길 차이가 아니었다. 띄어쓰기·끝의 '외'만 다른 업종 표기 2건, 종료 연도 오타 2건(리스트 값이 맞음), 서로 다른 직무의 전공이 다른 것 1건, 서로 다른 코드 체계(6자리 업종코드·5자리 표준산업분류) 1건.
- 결정
  - **소개서 사진**(`pipeline/e8_intro_photos`, V8 `institution_photo`)
    - 소개서 서식의 '회사 전경 및 활동사진' 칸에 든 사진만 넣는다. 얼굴이 보이는 사진도 그대로 둔다(서식의 홍보 사용 문구).
    - 칸인지는 PDF 글자 층의 제목, 또는 쪽 그림을 본 Claude(구조화 출력 `photo_section`)로 안다. 회사가 서식 대신 낸 소개 책자·슬라이드(더에스엠씨·세정·로젠)는 넣지 않는다 — 디자인 조각이 잘게 나뉘어 있어 '사진'이 아니다. 에이비티아시아 소개서에는 사진 칸('3. 기타 첨부자료')이 없다(홍보자료를 따로 냈다).
    - 자르기: PyMuPDF가 알려 주는 그림 자리를 쪽 그대로 다시 그려 자른다(긴 변 1,000px JPEG). 그림 자리를 PDF에서 알 수 없는 쪽(쪽 전체가 한 장의 스캔인 제이숲, 사진이 가는 띠로 잘려 들어간 빌딩닥터)은 사람이 자리와 캡션을 `manual_crops.json`에 적는다.
    - 캡션: 글자 층이 있으면 원문에 그대로 있는 문구만(`TEXT`), 글자 층이 없으면 Claude가 읽은 문구(`VISION`, 사람이 한 장으로 확인), 사람이 적은 것은 `MANUAL`.
    - 파일은 로고처럼 `static/photos/{기관 id}/{순번}.jpg`, 응답은 `photos[].path`(ADR-0019와 같은 방식, 로그인 없이·캐시 하루). 2026-2: 14곳 55장, 5.6MB.
  - **수기 전문**(V8 `testimonial` 열 추가): 한 줄 소개·회사 소개·실습 결과 문단·소감과 수기에 적힌 학과·학년을 넣는다(→ 학과·학년은 ADR-0037에서 뺐다). 이름은 추출하지 않고 수기 속 사진은 넣지 않는다. 화면은 '우수 참여수기 기준'(학교가 고른 수기)임을 밝히고, 기관을 평가하는 데 쓰지 않는다. 실습 결과 사실 구절(`outcomes`)은 추천 근거용으로 그대로 둔다(ADR-0020).
  - **검토 알림 소음 줄이기**
    - 문서 내부 불일치(AI)는 두 원문이 표기만 다르면 만들지 않는다(`build_seed.trivial_difference`): 띄어쓰기·문장부호·끝의 '외/등'만 다름, 한쪽이 다른 쪽을 품음, 글자 한두 개 차이(짧은 쪽의 15% 이하). 숫자가 하나라도 다르면 표기 차이가 아니다(날짜·금액·코드).
    - 리스트↔계획서 실습기간은 계획서 값이 스스로 말이 안 되면(종료일이 시작일보다 앞) 오타로 보고 리스트 값을 쓴다. 알림은 만들지 않는다.
    - 그 밖에 사람이 '알릴 필요 없음'으로 본 것은 `curated/alert_dismissals.json`에 이유와 함께 적는다(쓰이지 않는 항목이 있으면 시드 만들기가 멈춘다). 뺀 알림은 `out/review_alerts_dropped.csv`로 남긴다.
    - 운영계획서 추출 프롬프트(M2)에도 같은 기준을 넣었다 — 표기 차이·다른 직무의 차이·다른 코드 체계는 기록하지 않고, 확실하지 않으면 기록하지 않는다. 다음 추출(센터 업로드)부터 적용된다.
    - 2026-2: 12건 → 6건(선호 전공 4 · 실습지원비 1 · 주차 계획과 실습기간 1).
- 이유
  - 사진·수기 전문은 '이 회사에서 무슨 일을 하나'를 학생이 직접 판단하게 해 준다. 둘 다 학교가 학생에게 배포한 자료다.
  - 수기 치우침은 빼서 가리는 것보다 '우수 수기'라고 밝히고 보여 주는 편이 학생에게 정직하다.
  - 알림이 많으면 진짜 차이(선호 전공·지원비)가 묻힌다. 표기 차이는 규칙으로 판정할 수 있어 코드가 거르고, 판단이 필요한 것만 사람이 적는다.
- 확인
  - 사진: 소개서 18개 → 후보 605개 중 사진 칸 밖 550개를 뺌, 55장. 한 장으로 모아 사람이 봤다(캡션·자르기).
  - 알림: `trivial_difference` 단위 테스트(`pipeline/seed/test_seed.py`) — 업종 표기 두 쌍은 표기 차이, 산업분류코드·금액·주차는 아님, 세정 전공 목록은 아님(사람이 dismiss).
- 회사가 따로 낸 홍보자료 PDF(에이비티아시아 3개·에퀴코리아·빌딩닥터)는 보지 않았다.
- 다시 볼 때: 센터가 새 회차 소개서를 올리면(서버 추출) 사진 칸 판정을 같은 규칙으로 옮길 때, 기관이 사진 사용을 거부할 때, 알림 기준에 걸러야 할 새 유형이 생길 때.
